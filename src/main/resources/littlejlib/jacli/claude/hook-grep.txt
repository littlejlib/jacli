That is a symbol question asked as a text search, and jacli answers it by resolution rather than by spelling. implements/extends <Type> -> jacli impls <Type>, which also finds INDIRECT subtypes that never name the interface in their own declaration - a text search cannot. A method name with parens -> jacli refs Type#method for every use with the right overload, or jacli callers Type#method before changing a signature; both exclude same-named methods on unrelated types. interface/class/record <Name> -> jacli def <Name>. A hit you want to read around -> jacli at <file>:<line>. Several symbols in one call: jacli refs A B C. Text search stays right for string literals, comments, poms and resources - this is only about symbols.
